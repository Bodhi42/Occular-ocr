# Occular-OCR 0.5.2 — release notes and publication checklist

Status: prepared locally; not published.

## Release notes

- Adds the experimental, CPU-only RU/EN recognizer `svtr_lcnet_wsp`, selectable
  with `ocr(..., recognizer="svtr_lcnet_wsp")` or `ocr --model svtr_lcnet_wsp`.
- Uses the exact research checkpoint, with 384 changed weights and one bias;
  verifies its SHA-256 and the original charset before inference.
- Adds explicit errors for unsupported GPU and multilingual settings.
- Adds a paired image/PDF comparison example producing standalone HTML/JSON,
  regression tests, and a separate frozen scientific reproduction package.
- The default remains the original `svtr_lcnet`. Existing weights, detector,
  preprocessing, width buckets, decoding, public signatures and dependency
  requirements are unchanged. Ordinary users do not download or receive the
  alternative automatically. No DBNet edit is included.

The WSP option targets padding robustness, not universal recognition gains.
CUDA quality is not validated. Source and derivative-weight licensing remain
separate; see [the model documentation](../weight-space-programming.md).

## Known pre-existing test failure

`tests/test_code_lock.py::test_inn_kpp_digits_kept` fails both on the public
0.5.1 base (`15604d00cb1dc02e348bb2157b98ab215cf7154d`) and this candidate in
the same environment. The test expects preservation of `ИНН2/КПП3`, whereas
the existing digit-dominance rule does not preserve it in that context.
The decoder and the test are unchanged. This is reported rather than masked
with a skip or a decoder change. Review this known issue before publishing.

## Stage the exact checkpoint (no upload)

In a development environment with numpy, onnx and onnxruntime:

```bash
python tools/prepare_wsp_weights.py \
  --original /path/to/recognizer_svtr_lcnet_fp32.onnx \
  --edited /path/to/lcnet_se_guard.onnx \
  --charset /path/to/recognizer_charset.txt \
  --output release_artifacts/0.5.2/huggingface
```

This verifies both full-file hashes, exactly 385 changed parameters, identical
non-parameter ModelProto content, and CPU ONNX Runtime loading with multiple
batch sizes and widths. It copies the checkpoint unchanged and stages its
metadata and derivative license. It performs no network writes.

## Hugging Face publication — separate approval required

Repository: `Shivin11/occular-ocr`. Publish these three files only:

1. `recognizer_svtr_lcnet_wsp_fp32.onnx`
2. `recognizer_svtr_lcnet_wsp.metadata.json`
3. `recognizer_svtr_lcnet_wsp_LICENSE.md`

Do not overwrite any original model, charset, or existing repository metadata.
Use an account with write access. After explicit approval, the following can
upload just this allowlist; do not place tokens in scripts or reports:

```python
from huggingface_hub import HfApi
HfApi().upload_folder(
    repo_id="Shivin11/occular-ocr",
    folder_path="release_artifacts/0.5.2/huggingface",
    allow_patterns=[
        "recognizer_svtr_lcnet_wsp_fp32.onnx",
        "recognizer_svtr_lcnet_wsp.metadata.json",
        "recognizer_svtr_lcnet_wsp_LICENSE.md",
    ],
    commit_message="Add optional experimental SVTR-LCNet WSP checkpoint",
)
```

Download that file at the resulting HF commit into a fresh cache and verify
SHA-256 `24c5db4e64ad0a9bb8859b501670eff68969264ff0bee8af7130e3eb50f565f6`.
Record the HF commit in the release validation report. Test actual lazy loading
with no local WSP file before publishing the Python package. This final live
check cannot be done before the weights are uploaded. Existing user revision
pins are not changed automatically.

## Python/GitHub publication — separate approval required

1. Review the complete change and known baseline test failure; rerun the
   documented checks in the prepared release environment.
2. Build with `python -m build --outdir release_artifacts/0.5.2/dist`. Inspect
   the wheel and sdist: no ONNX, language models, private documents or research
   fixture; no new mandatory dependencies. Run `python -m twine check`.
3. Install the wheel in a clean environment; check image/PDF API, CLI, both
   decoders, model switching and the post-upload HF download.
4. After approval, commit/merge the reviewed release change, tag `v0.5.2`,
   publish the checked distributions to PyPI and create GitHub release notes
   from the section above. Do not include the ignored `release_artifacts`
   directory in a source commit or blindly upload its contents.

The public research fixture contains generated text only. It is available in
GitHub source, separately from the lightweight Python distribution. There is
no claimed public arXiv identifier until a real preprint URL exists.
