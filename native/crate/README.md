# occular-decode

Нативный (Rust) декодер для Occular-OCR: CTC prefix beam search + 4-граммная языковая модель.
Замена чистопитоновской связки `pyctcdecode` + `occular._pylm`, выдаёт **тот же текст**.

## Что это даёт

Замерено на документах из `../docs` (93–24 строки на страницу, beam=100, CPU 4 потока):

| Страница | строк | Python | Rust построчно | Rust пакетом |
|---|---:|---:|---:|---:|
| spravka_o_dohodah | 93 | 0,116 с | 0,020 с | 0,006 с |
| gazeta_dve_kolonki | 79 | 0,123 с | 0,024 с | 0,006 с |
| schet_na_oplatu | 64 | 0,318 с | 0,032 с | 0,010 с |
| foto_cheka | 44 | 0,093 с | 0,017 с | 0,004 с |
| sample_page (англ.) | 39 | 0,107 с | 0,015 с | 0,004 с |

То есть ×5–13 на строку и ×17–48 на страницу (пакетный вызов раскладывает строки по ядрам).
Совпадение с Python-декодером — 100 % на 343 строках шести страниц.

**Загрузка модели** (`compact_lm.npz` 268 МБ + `unigrams.txt` 25 МБ):

| | время | RSS после загрузки | RSS после страницы |
|---|---:|---:|---:|
| чистый Python | 2,58 с | 0,95 ГБ | 2,50 ГБ |
| Rust, копия через numpy | 1,59 с | 0,93 ГБ | — |
| **Rust, mmap** | **0,72 с** | **0,39 ГБ** | **2,01 ГБ** |

`Decoder.from_npz` отображает архив в память и читает n-граммы прямо оттуда: массивы никто не
копирует, страницы файловые — они общие между процессами (важно для PDF-воркеров и веб-сервисов)
и вытесняются под давлением памяти. Словарь тоже отображается, сортируются только смещения строк,
сами слова не копируются.

Плата за это — невыровненные чтения при бинарном поиске: декод примерно на 8–12 % медленнее, чем
с копией в куче. На фоне страницы это 0,3–1 мс, так что размен в пользу mmap очевиден; если
понадобится обратно — конструктор с numpy-массивами никуда не делся.

## Как устроено

* состояние LM — четыре 64-битных хеша суффиксов контекста, а не кортеж слов: ключ n-граммы
  считается инкрементально, без пересборки строк;
* n-граммы ищутся бинарным поиском по отсортированным `u64` (как и в `_pylm`, но без numpy);
* словарь префиксов — отсортированные смещения в отображённый файл вместо 2 млн python-строк;
* `compact_lm.npz` (zip без сжатия, zip64) разбирается и отображается своими силами — см. `src/npz.rs`;
* тексты лучей разделяются через `Rc<str>`, копируется только изменившийся кусок;
* `decode_batch` считает строки страницы через rayon, GIL на это время отпускается.

### Важная деталь про паритет

`pyctcdecode._merge_beams` при коллизии ключа `(text, word_part, last_char)` оставляет поля
**последнего** луча, то есть последнее разбиение `text` / `next_word`. На финальном шаге
(скоринг с `</s>`) разбиение решает, скорится ли последнее слово или пустая строка, а пустая
строка получает штраф около −26 и выбрасывает гипотезу фильтром выбросов. Из-за этого декодер
иногда теряет лучшую по акустике гипотезу: например, `.11` вместо `11` (−11,63 против −4,29).

Порт повторяет это поведение буквально, чтобы быть drop-in заменой. Если захочется «починить» —
`Decoder(..., keep_first_split=True)` оставляет первое разбиение: на наших страницах это меняет
2,6 % строк, часть в лучшую сторону (`11`, `1 400,00`), часть в худшую (`E. 4` вместо `Е. А.`).
Решать, что правильнее, нужно замером на реальном корпусе, а не на глаз.

## Сборка

```bash
maturin develop --release      # локально, в текущий venv
maturin build --release        # abi3-колесо для Python 3.8+
```

Колёса под все платформы собирает CI: `.github-workflow-wheels.yml` (положить в
`.github/workflows/`). Пользователю компилятор не нужен — `pip install` берёт готовое колесо;
если колеса под платформу нет, `occular-ocr` молча остаётся на чистом Python.

## Использование из библиотеки

Ничего делать не надо: `occular.decoder_lm.LMDecoder` сам подхватывает модуль, если он
установлен. Отключить принудительно: `OCCULAR_NATIVE_DECODER=0`.

```python
import occular_decode
# из файлов (быстрый путь, mmap)
dec = occular_decode.Decoder.from_npz(labels, "compact_lm.npz", "unigrams.txt",
                                      alpha=0.5, beta=1.0, beam_width=100)
# или из уже загруженных numpy-массивов
dec = occular_decode.Decoder(labels, keys, logps, backoffs, "unigrams.txt",
                             alpha=0.5, beta=1.0, beam_width=100)
text, logit_score = dec.decode(logits_tc)          # одна строка, [T, C] float32
pairs = dec.decode_batch([l1, l2, ...])            # страница целиком, параллельно
```
